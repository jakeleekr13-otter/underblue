# 독립 AI 프리셋 내부의 Core AI 후처리 검토

작성일: 2026-10-06
수정일: 2026-10-07 — QA·조건부 보완 제안 검토 반영
상태: **개발 보류.** 초기 복원 모델의 사용자 비교에서 체감 이득을 확인하지 못했다. [파일럿 결과](AIRefinerPilot.md)

최신 제품 방향은 Custom 오른쪽의 **독립 AI 프리셋**이다. Custom + AI 토글이나 현재 선택한 프리셋에 덧붙이는 공통 기능이 아니다. 전체 단계와 완료 조건은 [AI 프리셋 개발 계획](AIPresetDevelopmentPlan.md)을 따른다.

이 문서에서 말하는 기본 보정 결과는 **AI 프리셋 내부에서 고정 조건으로 생성하는 결과 B**다. 직전에 선택한 프리셋의 결과나 Custom 조정값을 상속하는 뜻이 아니다. AI용 기본 보정 방식과 강도 0%의 의미는 아직 미정이다.

## 제안

기존 프리셋의 Core ML + Core Image/Metal 경로를 유지한다. AI 프리셋을 선택했을 때만 자신의 기본 보정 B를 생성하고, 그 뒤에 이미지 복원 처리를 수행하는 방향을 검토한다. 후처리는 AI 프리셋 내부의 처리 순서다.

첫 후보는 동일 해상도의 약한 노이즈 제거와 디테일 보존이다. 확대가 필요할 때 별도의 2× 초해상도 기능을 검토한다. 생동감을 높이기 위한 색·대비 조절은 분리해 평가한다. 단순히 채도나 샤프닝을 높인 결과를 화질 개선으로 판정하지 않는다.

[앞선 실험](CoreAIExperiments.md)은 깊이 모델의 실행 경로 비교였다. 그 결과만으로 이미지 복원 후처리의 효과를 판단할 수 없다. Core AI는 실행 수단이며, 이 작업에는 Depth Anything이 아닌 **이미지 복원 모델**이 필요하다.

평가 모델의 피드백으로 보완하는 제안은 [QA·보완 설계 검토](AIQualityAssessment.md)에 반영했다. 첫 단계는 UIQM을 포함한 오프라인 다면 평가와 복원 모델 단독 비교다. QA 점수를 복원율로 표시하거나, 공개 모델들이 해석 가능한 결함 맵으로 바로 연결된다고 가정하지 않는다.

## 목표별 후보

| 목표 | 후보 | 기대할 수 있는 역할 | 현재 판단 |
|---|---|---|---|
| 같은 크기에서 더 깨끗하고 선명하게 | NAFNet-SIDD-width32 | 사진 노이즈 제거와 디테일 보존 | 첫 화질 실험 후보. 수중 보정 결과에 대한 효과는 미확인 |
| 작은 사진을 2× 확대 | EDSR r16f64 ×2 | 픽셀 수를 늘리며 확대 복원 | Apple Core AI 변환 예제가 있어 연동 출발점이 명확함 |
| 추가 복원 방식 비교 | SwinIR color denoise / lightweight SR | 노이즈 제거·확대용 별도 모델 | NAFNet 이후 후보 |
| 추가 복원 구조 비교 | Restormer | 고해상도 이미지 복원 | 모바일 경량 모델로 간주하지 않고 실제 기기 비용을 별도 확인 |
| 더 강한 질감 표현 | Real-ESRGAN | 열화된 사진의 확대와 질감 표현 | 원래 없던 질감이나 색 변화 가능성이 있어 우선순위 낮음 |

- [NAFNet 공식 모델 표](https://github.com/megvii-research/NAFNet#results-and-pre-trained-models)와 [SIDD width32 설정](https://github.com/megvii-research/NAFNet/blob/main/options/test/SIDD/NAFNet-width32.yml)은 공개되어 있다. SIDD는 수중 보정 결과 전용 데이터가 아니다. 흔들림 제거용 GoPro/REDS 가중치는 별개이며 SIDD 모델을 deblur 모델로 부르지 않는다.
- [Apple EDSR 안내](https://github.com/apple/coreai-models/blob/main/models/edsr/README.md)와 [변환 코드](https://github.com/apple/coreai-models/blob/main/models/edsr/export.py)는 2× 모델을 제공한다. 예제 기본 static 입력은 16×16, FP32이고 dynamic 범위는 8~256이다. 이 설정을 그대로 고해상도 사진 품질 시험으로 간주할 수 없다. 실제 타일 크기·정밀도·겹침 처리가 필요하다.
- [SwinIR](https://github.com/JingyunLiang/SwinIR)의 노이즈 제거와 확대는 서로 다른 모델이다. 기본 denoise 시험 스크립트는 합성 노이즈를 추가하므로 현재 사진 비교에 그대로 사용하지 않는다.
- [Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN)의 확대 결과는 시각적으로 선명할 수 있지만, 그 세부 묘사가 실제 장면과 일치하는지는 별도 문제다. 회귀 기반 복원 모델도 디테일 손실이나 가공에서 자유롭지는 않다.

EDSR을 일반적인 생동감 필터나 노이즈 제거 모델로 사용하지 않는다. 2× 확대의 효과는 **같은 출력 크기의 Lanczos 확대**와 비교한다.

## 현재 코드에 맞는 위치

현재 경로:

원본 → 색 분석·깊이 추정 → 물리 복원/색 보정/선명도/하이라이트 처리 → 두 결과의 혼합 → 사진 인코딩

독립 AI 프리셋의 처리 후보:

AI 전용 기본 보정 B → 모델용 색 변환 → AI 복원 → 강도 적용·출력 검증 → 기존 JPEG/HEIC 저장

구체적인 위치는 [PhotoProcessor.export](../UnderBlue/Processing/PhotoProcessor.swift)의 processed()와 같은 기존 처리로 AI 전용 B를 만든 직후, PhotoHDR.reexpand와 파일 인코딩 전이다. 이 호출은 AI 프리셋 분기에만 들어간다. 일반 저장 경로에 AI 작업을 공통으로 추가하지 않는다. 이미 저장한 JPEG를 다시 읽는 왕복 대신 메모리의 결과를 사용한다.

미리보기는 별도 경로다. 첫 화질 시험은 저장 전 비교 전용으로 진행할 수 있지만, 제품의 AI 프리셋은 선택 시 미리보기 처리를 시작해야 한다. 미리보기/저장 일치와 취소·캐시·실패 시 안내를 설계한다. 실패하면 AI 미적용 사실을 알리고 기존 보정으로 저장할 선택을 제공한다.

## 선명도 처리의 중복을 피하기

[FilterEngine.finishing](../UnderBlue/Processing/FilterEngine.swift)에는 이미 두 unsharp mask, 밝기 중심 선명도 전달, 광선 디테일, 미세 디테일, vibrance, highlight shoulder가 있다. 강한 AI 샤프닝을 덧붙이면 물의 입자와 노이즈, 피사체 테두리도 강조될 수 있다.

현재 colorStage는 referenceInput에 원본 image를 넣는다. 과거 CINoiseReduction 입력은 iOS의 경계/밝기 오류 때문에 제거됐다. [RestorationEngine](../UnderBlue/Processing/RestorationEngine.swift)의 저주파·미세 디테일 분리는 노이즈 증폭 억제용이며 범용 denoiser가 아니다.

첫 시험의 선택지는 다음과 같다.

- 보정 결과 전체를 AI로 바꾸기보다 복원 결과를 25%·50% 혼합해 비교한다. 이는 내부 복원 효과의 시험값이며, 제품의 AI 강도 슬라이더 의미나 기본값이 아니다.
- 큰 영역의 색과 밝기는 기존 결과에서 보존하고, 디테일 차이를 약하게 반영하는 방법을 함께 검토한다. 밝기 성분만 바꾸는 방식은 색 노이즈 제거에 한계가 있으므로 별도로 평가한다.
- 현재 출력 이후에 적용하는 것부터 시험한다. 효과가 부족하거나 이미 강조된 노이즈가 남으면 후속 비교에서 마지막 샤프닝 이전 위치도 검토한다.
- 하이라이트 보호는 이미 기존 경로의 끝에 적용된다. 후처리가 다시 클리핑/색 변화를 만드는지 확인한다. 기존 shoulder를 무조건 두 번 적용하지 않는다.
- 기존 SubjectMask는 보조 신호로 재사용할 수 있지만 전체 물/피사체 의미 분할이 아니다. 허용 면적이 0.5~25%라 큰 피사체나 산호 장면에서는 없을 수 있다.

## 색공간·해상도·HDR

현재 작업 공간은 linear Rec.2020/RGBAh이고 사진 출력은 Display P3다. 조사한 모델 샘플은 통상 RGB 0~1 이미지 입력을 사용하며, 현재 선형 광색역/HDR 값을 그대로 받는다고 확인되지 않았다.

첫 화질 비교는 **SDR sRGB 평가용 복사본**에서 수행한다. 다음 두 기준을 분리한다.

- A0: AI용 시험 기준 B의 출력 자체.
- A1: 모델과 같은 색공간·크기·입출력 변환만 거친 결과. AI 없음.

A0↔A1은 색 변환 자체의 영향을 보여주고, A1↔AI 결과는 모델의 영향을 보여준다. sRGB 왕복에서 색이 손실됐는데 AI 효과로 오해하지 않는다. 제품의 P3 보존은 별도 합격 항목이다.

모델 입력용 리사이즈를 이유로 원본 해상도를 낮춰 저장하지 않는다. 큰 사진은 충분한 문맥을 포함한 타일과 겹침/경계 처리를 검토한다. 2× 확대는 가로·세로가 각각 두 배가 되어 픽셀 수가 네 배가 된다.

현재 HDR 사진은 [PhotoHDR](../UnderBlue/Processing/PhotoHDR.swift)이 원본 HDR/톤매핑 SDR의 위치별 밝기 비율을 보정 결과에 적용한다. 확대나 내용 위치 변경은 이 정렬과 gain-map 처리에도 영향을 준다. 첫 실험은 SDR에 한정하고 HDR은 기존 경로를 유지한다. 16비트 이미지 파일 입출력 지원만으로 HDR 보존을 주장하지 않는다.

영상은 후순위다. 단일 사진 모델을 매 프레임 적용하면 질감과 노이즈가 프레임마다 달라져 깜빡일 수 있으므로, 시간적 일관성을 갖춘 별도 검증이 필요하다.

## 권장 첫 실험: 같은 크기에서 AI 노이즈 제거

### 데이터와 비교군

사진 8~12장을 AI 전용 고정 기본 보정으로 처리해 시험 입력을 만든다. 재현용 첫 후보는 Natural 0.8이며 최종 제품의 AI 기본 보정으로 확정한 값은 아니다. Custom이나 직전 프리셋은 읽지 않는다. 기존 m5/m6/O3 외에도 저조도, 녹색 물, 부유물, 산호·비늘, 가는 경계, 흰 피사체, 비교적 깨끗한 사진을 포함한다. 조정용과 확인용 사진을 미리 나누고 확인용을 보며 강도를 계속 맞추지 않는다.

| 비교군 | 내용 |
|---|---|
| A0 | AI용 고정 기본 보정 B |
| A1 | AI와 같은 입출력 변환만 적용한 출력 |
| B | A1에 약한 비AI 노이즈 제거/제한적인 선명도 조절 |
| C25 / C50 | A1에 NAFNet-SIDD-width32 결과를 각각 25% / 50% 혼합 |

같은 해상도·색공간·밝기·채도에서 PNG로 비교한다. 채도 증가와 확대는 이 시험에서 제외한다. 먼저 공개 PyTorch 모델로 화질 이득을 확인하고, 유망할 때 같은 가중치를 Core AI로 변환해 결과 오차와 기기 비용을 측정한다. 변환부터 시작해 효과 없는 모델에 시간을 쓰지 않는다.

### 기록할 항목과 진행 조건

- 전체 사진과 100% 확대를 이름을 가린 상태로 비교한다.
- 물·모래의 색/밝기 노이즈, 산호·비늘의 실제 디테일, 작은 기포 보존, 흰 배의 색, 테두리 halo, 클리핑, 얼룩과 타일 경계를 확인한다.
- 선명도 수치가 높아져도 노이즈 증가일 수 있다. 평탄한 영역의 노이즈와 의미 있는 텍스처를 따로 측정한다.
- 정답이 없는 실사진에서 PSNR·SSIM 또는 기존 출력과의 차이만으로 개선을 판정하지 않는다. 합성 노이즈 시험은 보조 자료로만 사용한다.
- 확인용 사진에서 노이즈/선명도 이득이 보이고, 비AI 비교군보다 낫고, 피사체 정보·색·하이라이트에 뚜렷한 퇴보가 없는 후보만 Core AI 변환 단계로 진행한다.
- 사진 한 장 전체 처리 시간, 최초 모델 로드, 반복 실행 시간, 피크 메모리, 12/48MP 입력 및 실제 iPhone 발열을 기록한다. 작은 깊이 모델의 30~40ms를 후처리 시간 예상치로 쓰지 않는다.

[scripts/color-eval](../scripts/color-eval/README.md)의 PNG·평탄 영역·비교 이미지 도구를 활용할 수 있다. 현재 지표는 8비트 sRGB 기준이며 P3/HDR 검증을 대신하지 못한다. Mac에서 유망해도 실제 iPhone 결과를 확인해야 한다.

## 제품화 판단

초기 모델은 화질 이득 조건을 통과하지 못해 제품화하지 않는다. 기존 경로를 유지하며 iOS 27 앱에도 해당 모델을 추가하지 않는다. 재개한다면 새 후보가 작은 블라인드 비교를 통과한 뒤에만 기술·상품 검토를 다시 연다.

NAFNet 교사와 작은 학생 모델을 이용한 파일럿, Core AI 변환, 사용자 비교는 완료했다. 앱 UI와 제품 경로는 변경하지 않았다. 파일럿 구현은 제품 브랜치에서 제거하고 결과만 기록한다.
