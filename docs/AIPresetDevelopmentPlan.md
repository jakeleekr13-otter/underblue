# 독립 AI 프리셋 개발 계획

작성일: 2026-10-06
수정일: 2026-10-07 — QA 평가와 조건부 보완 제안 검토 반영
상태: **개발 보류.** 2026-10-08 파일럿에서 체감 가능한 이득을 확인하지 못했다. [평가 결과](AIRefinerPilot.md)

## 보류 결정

1차 보정본과 두 보완 후보를 13장에서 비교한 결과, 8장이 차이 없음이었다. 독립 검증 2장도 모두 차이 없음이었고, 보완 선택 3장 중 2장은 “큰 차이는 모르겠다”는 조건부 선택이었다. 추가 모델 처리와 유료 기능을 정당화할 품질 이득이 확인되지 않아 P2에서 중단한다.

- 100장 평가 확대와 선호 미세조정을 진행하지 않는다.
- Core AI 모델을 앱 타깃에 포함하지 않는다.
- AI 프리셋 UI·강도 슬라이더·추가 구매를 구현하지 않는다.
- 기존 Core ML 깊이 추정과 Core Image/Metal 보정 경로를 유지한다.
- 현재 후보와 분명히 다른 방법이 작은 파일럿에서 먼저 개선을 보일 때만 재개한다.

아래 내용은 재개 시 사용할 계획 기록이다. 완료 또는 출시 약속으로 해석하지 않는다.

## 목표와 현재 결정

Custom 오른쪽에 **독립 AI 프리셋**을 추가한다. 기존 프리셋이나 Custom의 출력에 사용자가 켜는 공통 토글이 아니다. AI 프리셋은 자신만의 기본 자동 보정과 이미지 복원 모델, 강도 상태를 가진다.

사용자와 확인한 요구사항:

- Custom 조정값을 AI에 상속하지 않는다. AI를 선택해도 저장된 Custom 설정을 지우지 않는다.
- 다른 프리셋을 선택하면 그 프리셋의 현재 동작으로 돌아간다.
- 추가 AI 모델의 준비·분석·보정은 AI 선택 이후에 시작한다.
- AI 강도는 기존 프리셋/Custom 값과 별도로 관리한다.
- iOS 27 이상을 대상으로 하되 실제 기기·모델·사진 형식의 지원 여부도 확인한다.
- 기존 경로에 불필요한 AI 작업이 들어가지 않아야 한다.
- 별도 유료 애드온 가능성을 검토한다. 가격과 Pro 필요 여부는 미정이다.

앱에 이미 있는 Core ML 깊이 분석은 기존 공통 작업이다. 선택 시 시작한다는 조건은 **새 이미지 복원 AI 작업**에 적용하며, 기존 분석까지 제거하는 뜻은 아니다.

[깊이 모델 실험](CoreAIExperiments.md)의 결정은 유지한다. 기존 Core ML을 Core AI 깊이 추정으로 교체하는 것이 이번 개발 목표는 아니다.

## 확정 사항과 제안을 구분하기

| 항목 | 상태 |
|---|---|
| Custom과 동급인 독립 AI 프리셋 | 확정 |
| Custom 조정값을 읽지 않는 AI 전용 기본 보정 | 확정 |
| AI 선택 전 추가 모델 로드·다운로드·특수화·추론 없음 | 요구사항 |
| 실제 사진의 노이즈·디테일 개선 | 목표, 아직 입증 안 됨 |
| AI용 기본 보정에 Natural의 고정 값을 사용 | 시험 기준으로 제안. 최종 제품 방식 미정 |
| AI 강도 0%가 원본인지 AI용 기본 보정 결과인지 | 미정. UI 구현 전에 정의 |
| 사진/SDR/동일 해상도부터 검증 | 초기 개발 범위 제안 |
| 일회성 비소모성 AI 추가 구매 | 상품 방식 제안 |
| Pro 필수 여부, 상품 가격, 체험 저장 범위 | 미정 |

강도 0%의 의미를 앞선 제안에서 확정한 것으로 취급하지 않는다. 기존 프리셋과 맞추려면 0%=원본, 100%=AI 프리셋 완성 결과가 자연스러운 후보다. AI 디테일만 조절하려면 0%=AI용 기본 보정 결과가 된다. 어느 쪽이든 Custom이나 직전에 선택한 프리셋의 값은 사용하지 않는다.

## 모델 선정 원칙

여기서 최적 모델은 모든 사진에서 최고라는 의미가 아니다. **대상 수중 사진에서 화질 조건을 통과하고, 지원 기기의 시간·메모리·배포 크기 조건을 만족하는 후보**를 뜻한다.

우선순위는 다음과 같다.

1. 실제 피사체 정보와 색을 보존한다.
2. 기존 결과와 비AI 보강보다 체감할 수 있는 개선이 있다.
3. 프리뷰·저장 반응성과 메모리가 제품 범위에 맞는다.
4. 그 안에서 파일 크기·전력·기기 범위를 최적화한다.

처음부터 새 네트워크를 학습하지 않는다. 공개 복원 모델을 비교하고, 필요할 때 추가 학습·경량화·압축을 적용한다. Core AI는 실행 프레임워크이며, Apple이 제공하는 범용 기능을 호출하는 것만으로 수중 사진용 최적 모델이 생기는 것은 아니다.

초기 후보는 [NAFNet-SIDD-width32](https://github.com/megvii-research/NAFNet#results-and-pre-trained-models)다. 동일 해상도 노이즈 제거의 출발점이며 수중 사진 성능은 미검증이다. 화질이 부족하면 NAFNet의 다른 크기 또는 SwinIR를 비교한다. [EDSR ×2](https://github.com/apple/coreai-models/blob/main/models/edsr/README.md)는 확대용 별도 후보이며 첫 선별에서 같은 크기 노이즈 제거 모델과 순위를 섞지 않는다.

모델별 역할과 입출력 주의사항은 [후처리 검토](CoreAIPostProcessing.md)에 있다.

품질 평가 모델과 조건부 보완 구조는 [QA·보완 설계 검토](AIQualityAssessment.md)를 따른다. UIQM은 오프라인 보조 지표로 포함하되 유일한 정답이나 학습 목표로 삼지 않는다. 첫 복원 후보는 단독 실행으로 비교하고, 학습형 QA/조건부 모델은 추가 효과를 확인할 때 도입한다. 초기 UI에 품질 점수나 복원율 백분율을 넣지 않는다.

## 단계와 완료 조건

| 단계 | 작업과 산출물 | 다음 단계로 가는 조건 |
|---|---|---|
| P0. 기능 계약 | 독립 프리셋 동작, AI 전용 기본 보정, 강도 의미, 지원 범위 문서 | Custom 비상속과 일반 경로 보존 확정. 제품 선택 사항은 미정으로 명시 |
| P1. 비교 기준·QA 준비 | 사용 범위가 확인된 사진 목록·해시·장면 분류, 개발/확인 세트, A0/A1/비AI 비교군, UIQM 구성값과 색/노이즈/사람 평가표 | 같은 장면이 양쪽에 섞이지 않고 비교 조건이 고정됨. UIQM을 단독 합격 기준으로 쓰지 않음 |
| P2. 공개 모델 화질 선별 | 복원 모델 단독 결과, 전체/100% 확대 비교, 결함 표, 선호도와 지표 불일치 기록 | 확인 세트에서 체감 이득이 있고 주요 디테일·색·하이라이트가 악화되지 않음 |
| P3. 초기 Apple 기기 적합성 | 유망 모델의 Core AI 시제품, 변환 일치 검사, 실제 iPhone 시간·메모리 | 학습에 큰 비용을 쓰기 전에 연산 지원·고해상도 처리 가능성을 확인 |
| P4. 필요한 부분만 추가 학습 | 복원 모델 미세조정, 필요 시 학습형 QA/결함 라벨 및 조건부 모델, 재현 가능한 기록 | 단독 공개 모델보다 확인 세트에서 개선. QA 조건의 이득과 추가 비용을 별도로 검증 |
| P5. 정밀도·압축 최적화 | FP16/압축 후보별 화질·시간·메모리·크기 표 | 최적화 전후 계산과 실제 사진을 모두 검증하고 제품 조건 통과 |
| P6. 독립 AI 프리셋 연동 | 지연 로드·취소·캐시·강도·미리보기/저장·오류 복구 | 일반 경로 회귀와 빠른 프리셋 전환, 메모리 압박 검증 통과 |
| P7. 유료 기능 준비 | 지원 범위·권한·가격·미리보기/저장·복원 정책 | 실제 구매 가치 확인 후 상품 구성 확정. 미지원 기기에 판매하지 않음 |

P4는 필수가 아니다. 공개 모델로 충분하면 P5로 진행한다. 화질 조건을 통과하는 후보가 없으면 기능 출시를 보류한다.

## P1–P2: 첫 실행 단위

처음에는 8~12장으로 문제를 찾는 소규모 비교를 한다. 이 결과만으로 최종 모델을 선정하지 않고, 이후 별도의 확인 자료를 확대한다.

사진 목록에 다음을 기록한다.

- 사진 ID, 파일 해시, 촬영 장면/연속 촬영 그룹, 출처와 사용 범위.
- 해상도·방향·색 프로필·SDR/HDR 여부.
- 파란 물/녹색 물, 밝음/저조도, 평탄한 물, 산호·비늘·가는 경계, 부유물, 흰 피사체, 깨끗한 사진.
- 개발용/확인용 구분. 같은 촬영의 인접 프레임을 양쪽에 나누지 않는다.

UIEB 공식 배포 조건은 비상업용·학술용이다. 유료 제품의 학습/평가에 바로 사용할 수 있는 자료로 지정하지 않는다. 별도 허가나 상업적 사용 조건이 확인된 자료를 우선하며, 이미지 쌍과 품질 점수/결함 라벨도 구분한다. [데이터 조건과 QA 라벨 검토](AIQualityAssessment.md)

모델 입력 B는 AI 프리셋 내부의 고정 기본 보정 결과로 만든다. 초기 재현용 후보는 Natural 0.8이다. 이는 기존 평가와 비교하기 위한 **시험값**이고 제품의 AI 색감 결정이 아니다. Custom 설정이나 직전 선택 프리셋을 읽지 않는다.

비교군:

| 비교군 | 목적 |
|---|---|
| A0: 고정 기본 보정 B | 현재 기술의 기준 |
| A1: B에 모델과 같은 색/범위 변환만 적용 | 색 변환 손실과 AI 효과를 분리 |
| B1: A1 + 약한 비AI 노이즈 제거 | AI가 추가 비용만큼 유리한지 비교 |
| C25/C50: A1 + 복원 모델 결과를 25%/50% 혼합 | 디테일 보존과 노이즈 감소의 균형 탐색 |

C25/C50은 내부 모델 효과를 시험하는 값이다. 제품의 AI 강도 슬라이더 의미와 기본값은 별도로 정한다.

현재 처리가 끝난 사진에서 출발하며, 같은 해상도·노출·채도로 PNG를 만든다. 먼저 원본 PyTorch 모델로 효과를 확인하고, 유망한 후보만 Core AI로 옮긴다. 과도한 채도, 해상도 증가, JPEG 재압축이 좋아 보이는 원인이 되지 않게 통제한다.

[색 평가 도구](../scripts/color-eval/README.md)의 PNG와 영역 비교를 재사용하되, 현재 8비트 sRGB 지표를 P3/HDR 품질 증명으로 사용하지 않는다.

## 화질 합격 조건

다음은 평가해야 할 조건이며 이미 통과했다는 뜻이 아니다.

- 확인용 사진에서 현재 결과 및 비AI 결과와 이름을 가린 비교를 한다. 개선/동등/악화와 이유를 남긴다.
- 평탄한 물과 어두운 영역의 노이즈 감소와 산호·비늘의 정보 보존을 별도로 본다.
- 작은 기포·입자·가는 무늬를 지웠다면 노이즈 감소만으로 합격시키지 않는다.
- 흰 배·모래의 색, 원래의 물 색, 하이라이트·검은 영역, halo·번짐·타일 경계를 검사한다.
- 깨끗한 사진이 더 흐려지거나 인공적인 질감이 생기면 실패 사례로 기록한다.
- 정답 사진이 없는 경우 PSNR·SSIM이나 선명도 수치 하나로 개선을 판정하지 않는다.
- UIQM과 UICM/UISM/UIConM은 같은 구현·크기·범위로 기록하는 보조 값이다. 사람이 확인한 색 과보정·노이즈·디테일 손실과 충돌하면 점수 상승만으로 합격시키지 않는다.
- 평가 대상이 보완 전 B인지 보완 후 F인지 구분한다. 둘의 점수·특징을 기록하더라도 독립적인 확인 자료와 사람 평가를 유지한다.
- 확인 자료를 보며 계속 튜닝하지 않는다. 후보 변경 후에도 독립 확인 자료를 유지한다.

P2에서 선호도·결함 기록 방식과 허용 범위를 고정한 뒤 최종 확인에 사용한다. 제한된 사진으로 보편적인 화질 우위를 주장하지 않는다.

## P3–P5: Apple 기기용 모델 만들기

### 변환과 실행

- Core AI 산출물은 PyTorch/torch.export → coreai-torch → .aimodel 경로로 준비한다. ONNX를 필수 단계나 Core AI 기본 실행 포맷으로 두지 않는다.
- 후보 가중치와 소스 버전·해시·색공간·감마·입출력 범위·패딩을 고정한다.
- 타일 크기와 겹침을 정하고, 타일 실행이 전체 실행과 어떤 차이를 만드는지 검사한다. 전역 연산을 쓰는 모델은 타일 경계 밖의 문맥이 달라질 수 있다.
- 변환 전후 고정 입력과 실제 사진의 수치 차이를 기록한다.
- FP16 후보를 준비하되 정밀도 변경으로 색·디테일이 손상되지 않는지 확인한다.
- 자동/GPU/Neural Engine 선호를 실제 기기에서 비교한다. 선호 설정을 실제 장치 사용으로 간주하지 않는다.
- 이전 깊이 모델은 FP32 중간값 때문에 ANE 컴파일에 실패했다. 새 모델의 그래프와 로그를 별도로 점검하며, FP16으로 바꾸면 반드시 ANE가 된다고 약속하지 않는다.
- 공유 버퍼·GPU 입력 변환·타일 재사용은 결과 일치와 동기화를 확인한 뒤 적용한다.
- 모델 크기를 줄인 후 다시 화질·시간·메모리를 측정한다. P6 등 특정 비트 수를 먼저 제품 요구사항으로 고정하지 않는다.

[Apple 모델 통합 안내](https://developer.apple.com/documentation/coreai/integrating-on-device-ai-models-in-your-app-with-core-ai), [직접 압축 안내](https://apple.github.io/coreai-optimization/utils/coreai_compression.html), [Apple 공식 Core AI 모델 레시피 저장소](https://github.com/apple/coreai-models).

### 공식 Core AI 모델 저장소(apple/coreai-models) 참고

[apple/coreai-models](https://github.com/apple/coreai-models/tree/main/models)는 사전 변환된 바이너리(`.aimodel`) 파일을 직접 배포하는 것이 아니라, 검증된 오픈소스 모델을 한 줄 명령어로 `.aimodel`로 내보낼 수 있는 **공식 Export Recipe(변환 스크립트)**를 제공한다.

- **원클릭 공식 레시피 지원 모델 (`uv run models/<name>/export.py`)**:
  - **초해상화**: `models/edsr` (EDSR ×2 등 초해상화 모델을 즉시 추출 가능하며, 확대용 비교군 검증에 바로 사용 가능)
  - **깊이 추정**: `models/depth-anything` (Depth-Anything 공식 레시피 지원)
  - **세그멘테이션/객체**: `models/efficient-sam`, `models/sam3`, `models/yolo`
  - **생성/언어/오디오**: `flux2`, `sana`, `whisper`, `wav2vec2`, `qwen`, `gemma` 등
- **수중 복원/디노이징 모델 현황**:
  - NAFNet, Restormer 등 이미지 복원·디노이징 특화 모델은 현재 Apple 공식 카탈로그에 등록되어 있지 않다.
  - 따라서 1순위 후보인 NAFNet-SIDD는 카탈로그 레시피가 아닌, `coreai_torch` 저작 도구(`torch.export` → `coreai_torch` → `.aimodel`)를 사용해 PyTorch 체크포인트를 직접 변환해야 한다.
- **실행 환경**:
  - `uv` 기반 워크플로우를 사용하며, 타깃 기기 플래그(`--platform iOS` 등) 지정 가능. macOS/iOS 27.0+, Xcode 27.0+ 환경이 필요하다.

### 추가 학습이 필요한 경우

공개 모델이 수중 보정 결과의 노이즈와 디테일을 잘 구분하지 못할 때만 진행한다.

- 목적은 색을 임의로 다시 만드는 것이 아니라 정해진 색감 안에서 노이즈를 줄이고 실제 세부를 보존하는 것이다.
- 촬영 장면별로 학습/개발/확인 자료를 나눈다. 연속 사진과 잘라낸 조각도 같은 그룹으로 묶는다.
- 정답은 출처가 명확한 깨끗한 이미지/정렬된 자료 또는 관리된 열화 실험으로 준비한다. 현재 앱 출력을 유일한 정답으로 삼으면 기존 오류를 그대로 학습할 수 있다.
- 합성 노이즈만으로 실제 수중 결과를 대표한다고 가정하지 않는다. 현재 색 보정이 노이즈를 바꾸는 영향도 데이터 설계에 반영한다.
- 색 보존·구조·노이즈를 함께 평가하고, 초기에는 생성적 질감 추가보다 보수적인 복원을 우선한다.
- 큰 모델이 필요하면 그 효과를 확인한 뒤 작은 모델로 옮기는 경량화/증류를 검토한다.
- 코드 라이선스, 가중치 배포 조건, 학습 자료 사용 조건을 각각 기록한다.

QA 특징을 입력으로 쓰려면 공개 NAFNet/Restormer의 기본 인터페이스를 수정하고 학습해야 한다. 두 모델을 하나의 클래스나 파일에 넣는 것만으로 공유 인코더·멀티태스크 학습·속도 개선이 생기지 않는다. 상세 비교는 [QA·보완 설계](AIQualityAssessment.md)를 따른다.

학습 장비·시간·비용은 데이터와 후보를 확인한 뒤 산정한다. 이번 계획 작성으로 모델 학습을 실행한 것은 아니다.

### 성능 표에 반드시 포함할 항목

첫 로드/특수화, 준비된 상태의 처리, 화면 전체 미리보기, 100% 확대 영역, 12MP·48MP 저장, 피크 메모리, 반복 실행 발열, 취소 후 복귀를 각각 기록한다. 현재 iPhone 17과 판매 대상의 최저 사양 기기를 구분해 시험한다.

기존 깊이 분석의 32.96/40.81ms를 새 후처리의 목표 시간으로 사용하지 않는다. 실제 전체 사진의 초기 측정 후 미리보기·저장 시간 예산과 모델 크기 예산을 정하고, 후보별로 충족 여부를 표시한다.

## P6: 독립 프리셋과 기존 흐름 보호

프리셋 행:

Original · Natural · Tropical · Deep Dive · Custom · AI

AI는 프리셋을 대체 선택한다. 화면에 Custom + AI를 만들거나 Custom 조정값 위에 AI 토글을 얹지 않는다.

처리 흐름:

1. 사진 열기와 기존 공통 분석은 현행대로 수행한다.
2. AI 이외 프리셋에서는 해당 프리셋의 현재 처리만 한다.
3. AI 선택 시 AI 전용 기본 보정 B를 생성하고 모델 준비·미리보기 복원을 시작한다.
4. 준비 중에는 마지막 유효 이미지를 유지하되 AI 적용 완료처럼 표시하지 않는다. 취소와 다른 프리셋 선택을 허용한다.
5. 강도 변경은 준비된 결과의 혼합을 기본으로 하며 매번 추론하지 않는다. 강도 조건을 입력으로 받는 모델이 필요하다면 이 UX 계약을 다시 평가한다.
6. 다른 프리셋·사진·화면으로 이동하면 추가 작업을 취소하고 늦게 도착한 결과를 버린다.
7. AI 실패 시 알리고 기존 보정으로 저장할 선택을 제공한다. AI 적용 성공으로 가장하지 않는다.

AI 상태·강도·작업·캐시를 기존 설정과 분리한다. 캐시에는 이미지/방향/해상도/색공간/AI 기본 보정 버전/모델 버전이 반영돼야 한다. 변경된 사진이나 버전에 이전 결과를 쓰지 않는다.

작은 미리보기와 원본 크기 추론은 디테일이 달라질 수 있다. 100% 확대와 내보내기 비교에 실제 원본 해상도 처리를 사용해, 구매 전 미리보기가 저장 결과를 과장하지 않게 한다.

일반 경로 수용 조건:

- AI 선택 전 추가 복원 모델 다운로드·로드·특수화·추론 카운터는 각각 0.
- 기존 깊이 분석과 추가 복원 모델 작업을 구분해 계측.
- 같은 기기·입력·설정·렌더링 조건에서 기존 프리셋 출력이 기준 결과와 일치.
- 기능 추가 전/후 일반 미리보기·저장 시간과 메모리를 반복 비교하고, 사전에 정한 측정 허용 범위 내인지 확인.
- Custom 값은 보존되고 AI에 반영되지 않음. 기존 강도와 AI 강도도 서로 변경하지 않음.
- AI 해제/사진 변경 후 이전 결과가 화면을 덮어쓰지 않음.
- 이미 제출한 GPU 작업의 즉시 중단까지 약속하지 않음. UI 복귀, 대기 작업 취소, 타일 단위 중단과 결과 폐기를 검증.

## 색과 지원 범위

첫 비교는 SDR sRGB에서 진행한다. 제품의 Display P3와 HDR 지원은 별도 검증 대상이다. 원본 저장 해상도를 모델 입력 크기로 낮추지 않는다. HDR 원본의 gain-map 정렬과 밝기 비율 처리, 영상의 시간적 안정성은 후속 범위로 둔다.

iOS 27이라고 모든 기기·모델·포맷이 자동 지원되는 것은 아니다. 표시/구매/실행 조건은 검증한 지원 범위에 맞춘다.

## P7: 별도 애드온

아직 상품을 만들거나 가격을 정하지 않는다. 화질과 기기 조건을 통과한 뒤 다음을 결정한다.

- Pro 구매자용 추가 상품인지, AI 사진 저장 권한을 포함한 독립 상품인지.
- 비구매자의 무료 미리보기와 체험 저장 범위.
- 기본 Pro와 AI 각각의 기능·가격·구매 복원·환불 처리.
- 미지원 기기나 실패한 모델에 구매를 유도하지 않는 조건.
- AI 구매 후 저장 단계에서 예상하지 못한 추가 Pro 결제가 나타나지 않는 안내.

현재 Pro 구매자의 기존 기능은 유지한다. 새로운 애드온의 유료 가치는 실제 전후 이미지에서 확인되는 개선으로 설명한다.
